# HU-01: Proteger el token de autenticación en el cliente

## Origen

- **H-WEB-01** — Token bearer almacenado en `localStorage` (pendiente; severidad media).
  - `web/src/app/login/login.component.ts:47`
  - `web/src/app/dashboard/dashboard.component.ts:36`
  - `web/src/app/dashboard/dashboard.component.ts:44`

## Contexto

El cliente persiste el token de autenticación en `localStorage` y lo lee para consultar tareas. Según H-WEB-01, código JavaScript del mismo origen puede leerlo y una inyección de script exitosa podría exponerlo. La matriz confirma el almacenamiento y la lectura; no reporta una explotación observada.

## Ajustes necesarios

- Definir un mecanismo para mantener la sesión y autorizar las consultas que no exponga el token a lectura desde JavaScript mediante `localStorage`.
- Migrar el login y la consulta de tareas al mecanismo acordado, conservando el flujo autenticado existente.
- Añadir pruebas que comprueben tanto la protección del token como la continuidad de la consulta autenticada.

## Criterios de aceptación

- Una prueba de login exitoso verifica que el token de autenticación no se persiste en `localStorage`.
- Una prueba del dashboard verifica que la consulta autenticada de tareas funciona con el mecanismo acordado y que el flujo no lee el token desde `localStorage`.
- Una prueba del flujo login→tareas verifica que, después de autenticarse, se puede completar la consulta protegida sin que el token quede disponible mediante `localStorage`.

## Evidencia esperada

- Resultados aprobados de las pruebas unitarias de login y dashboard que verifican los criterios anteriores.
- Resultado aprobado de una prueba funcional del flujo login→consulta de tareas.
- Revisión del código que confirme que el token no se escribe ni se lee desde `localStorage`.
